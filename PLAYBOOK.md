# Japan by Station: production playbook

Ling runs **Japan by Station**: japanbystation.com (Japan-only English travel guides) and Instagram **@japanbystation**.
Each Reel answers ONE traveler question and gives the solution. Viewers comment a KEYWORD and n8n DMs them the guide page.
**The guide page must be live (and its keyword in keywords.json) before its Reel is queued.**

## 0. Session setup (every fresh session)
```
git clone -q -b studio https://github.com/fippystore-japanbystation/japanbystation.git ~/jbs/studio   # add_repo first if git is refused
cd ~/jbs/studio && python3 jbs.py setup      # clones main + media into ~/jbs, downloads the Kokoro voice model
python3 jbs.py status                        # what's queued, which keywords exist
```
Always finish with `python3 jbs.py save "what you did"` so the next session has your new sources (no Cloudflare build).

## 1. Voice and facts (non-negotiable)
- NEVER repeat a topic. Before writing anything, read the DONE list in TOPICS.md and the existing site/guides and reel/specs. Add every new guide/Reel to DONE.
- Professional team voice: "we suggest", "we'd take", "our pick". Never "Honestly?", no overly friendly AI phrasing, no hype.
- Never invent team names, credentials or personal stays. We build guides from official sources.
- Every time, price, opening day and distance comes from a source you found this session (operator, airport, city tourism bureau such as osaka-info.jp / kyoto.travel, the venue itself). If only blogs say it, write "about" or leave it out. Put sources in the guide's `sources` field with the check date.
- Explain WHY (minutes saved, price, fewer changes, who it suits). Say who it does NOT suit.
- No affiliate or commission wording inside videos or captions. No fake urgency.
- NOT ALWAYS DOTONBORI / NAMBA (Ling, 23 Nov; guides AND Reels). Too many Osaka pieces end with "stay in Namba, walk to Dotonbori". Every Osaka piece must include at least one less obvious area as a real option, framed as "besides Namba / Dotonbori, consider X, because …" with 1–2 researched whys (e.g. Tenma, Kitashinchi, Nakazakicho, Tanimachi, Kyobashi, Fukushima, Bentencho, Shin-Osaka, Kitahama), matched to who it suits. Do not use Dotonbori as the reference point in more than one answer per piece. Same idea in Tokyo: not every answer is Shinjuku or Shibuya.

## 2. Website guides
DEEP TEMPLATE (Ling, 23 Nov; EVERY new guide, briefs included): copy `site/guides/tenma-tenjinbashisuji-local-guide.html`. Ling: "not surface level", a real 3–5 minute read (about 700–1,100 words), quality over speed. A place may be covered again from a new angle (Ling: one place can be told more than once) — link the related guides both ways.
  Order (use the sections that fit the question; brief guides keep their A/B/C answers and verdict inside this frame):
  1. Hero + lede that ANSWERS FIRST (who should go / what to pick) and why, in 2–3 sentences; byline "About a N-minute read · facts checked <date>".
  2. "Who it suits, and who it doesn't" (`.fit` yes/no boxes).
  3. Getting there (exact lines/stations, which pass covers it).
  4. Eat like a local: named places with what to order, price level, closing day, queue tip; at least one photo (`<figure class="photo">` with alt text + caption).
  5. A half-day route with times (`ol.route`, `span.t`) when it's an area guide.
  6. Where to stay: three bases as cards, each = who it suits + one downside + a link whose text is UNIQUE and evocative ("Wake up quiet, be in Kyoto by mid-morning →"), never "See hotels near X", never the word "affiliate".
  7. A "hot" experience box (`.hotbox`) where one really exists (food walk, sell-out tickets) — check on Klook/osaka-info that it exists.
  8. "📅 Good to know before you book" (`.bookbox`): SOFT FOMO from real facts only (annual fixed dates, reservation-only spots, real closures, "most hotels offer free cancellation"); never "book now", never invented scarcity.
  9. Nearby, if you have more time; 10. ONE MORE THING; 11. one-line affiliate disclosure at the very bottom (`p.disclose`); 12. Keep planning links.
  Every <img> has descriptive alt text; hero_alt is used for og:image:alt (build does it). Photos: Pexels ids that really show that place (look first). FAQ 3–4 with direct answers.
One file per guide: `site/guides/<slug>.html`. The build picks it up automatically (home "Latest posts", /guides index, sitemap, llms.txt, JSON-LD Article + Breadcrumb + FAQPage, keywords.json).
Header block (JSON, must parse):
```
<!--meta
{"title":"…","desc":"meta description, ~150 chars","city":"Kyoto","cat":"Where to stay","tag":"coral|mint|sky|sun|lilac|pink",
 "hero":PEXELS_PHOTO_ID,"hero_alt":"…","card":"one-line summary for cards","date":"YYYY-MM-DD","keyword":"UNIQUEWORD","order":0,
 "faq":[["question","answer"],…],"sources":"… Checked D Month YYYY."}

```
Body: copy the structure of an existing guide (e.g. `site/guides/osaka-local-markets.html`): hero → lede (answer first) → byline with check date → `band` sections (`band plain|namba|umeda|tennoji`) with `card noimg` fact cards → `tipbox` "Our suggestion" → booking CTA → "Keep planning" links.
- Images: `src="pexels:ID:WIDTH"` (Pexels photo id). Pick photos that really show that place; Tokyo photos never on Osaka pages.
- IMAGES MUST DISPLAY (Ling, 23 Nov): the build only makes `.jpeg` URLs, and some Pexels photos are PNG only (e.g. 35834190 broke a live hero). Before using any id, load `https://images.pexels.com/photos/ID/pexels-photo-ID.jpeg?auto=compress&cs=tinysrgb&w=300` in the browser (new Image() onload/onerror); reject ids that fail. After deploy, check every image on each new page plus /, /guides and the city page loads (no broken images), and fix + redeploy at once if any is broken.
- Affiliate links only inside content, `rel="sponsored noopener" target="_blank"`: Booking.com search `https://www.booking.com/searchresults.html?ss=<Area>%2C+<City>` (Travelpayouts Drive script converts it), Klook search `https://www.klook.com/search/result/?query=…` for tours/passes/transfers. A page with no affiliate link is fine.
- More approved programs (Ling, 23 Nov; already active on Travelpayouts, the Drive script converts plain official links): Airalo / Yesim (Japan eSIM — https://www.airalo.com/japan-esim , https://yesim.app/), Welcome Pickups / Kiwitaxi (airport transfers — https://www.welcomepickups.com/ , https://kiwitaxi.com/), Radical Storage (luggage storage — https://radicalstorage.com/), Go City (https://gocity.com/), Tiqets (https://www.tiqets.com/). Put ONE where the reader is deciding that exact thing (eSIM in arrival guides, transfer in airport guides, storage in early-arrival / last-day guides). Booking.com, Agoda, Trip.com etc. are still under review: keep the Booking.com search links (they start earning once approved).
- HONESTY about affiliate links: they do NOT make anything cheaper for the reader (same price as booking direct). Never write "cheaper/best price/save" for a link unless the guide shows a same-date price comparison proving it. Frame them as convenience (book in English, pay in your currency, skip the ticket queue, free cancellation where the page says so).
- ONE MORE THING (Ling, 23 Nov; EVERY guide, new and old). Each guide ends (before "Keep planning") with ONE extra that a quick Google search or AI answer would not give, in `<section class="wrap sec onemore">` with `<h2>One more thing: …</h2>`, 2–4 sentences + a small source line. Example: site/guides/nakazakicho-vs-umeda-hotel.html (Yamatatsu croquettes outside Nakazakicho Exit 2). Rotate the type:
  - FOOD: a place locals actually go (butcher croquettes, an old kissaten, a standing bar, the shotengai bakery). Must be backed by Tabelog / Retty / Google Maps reviews or a local tourism site; name it, say where (exit / metres), payment quirks, what to order. Say "popular with locals" only if the source says so.
  - A VIEW / SCENE: where to stand or what time to go to see something most people miss (a bridge, a rooftop, a river walk at dusk).
  - A LOCAL HABIT: how people who live there use the place (morning shotengai, sento, a neighbourhood shrine).
  - A SMART TIP: the same experience, easier or cheaper (with the number and why).
  - A LESS-DONE ACTIVITY: something few visitors do there (a workshop, a morning sento, a ferry, a hike from the station). Later (Ling, 23 Nov) these may link to a bookable GetYourGuide/Klook activity, only via approved programs; GetYourGuide is NOT approved yet, so no GetYourGuide links until Ling says so.
  HONEST TONE (Ling, 23 Nov): if it's good, just say it's good; no forced "but". Mention a downside only when reviewers really flag one that matters (e.g. "cash only", "20-minute queue at lunch", "some find it too greasy"). Attribute it ("Tabelog reviewers say…"), never invent opinions.
  It must be EVERGREEN: no dated events, festivals or limited menus (they expire). Never "locals told us" / "our favourite" (we don't claim visits). Facts checked this session; add the source to the `sources` field.
  STATUS: all existing guides got one on 23 Nov 2026 (osaka-where-to-stay is in build.py ONEMORE_OSAKA). Never reuse a place already used in another guide (grep "One more thing" site/guides/*.html). If a page somehow lacks one (grep -L onemore site/guides/*.html), add it before writing new briefs.
- Keyword: one short UPPERCASE word, unique (build asserts). It is what viewers comment.
- SEO/GEO: answer in the first paragraph, 3–4 FAQ entries with direct answers, real numbers, internal links to related guides.
- Deploy: `python3 jbs.py deploy-site "Add <slug>"` (builds, copies to main, pushes → live in ~1 min). **Batch several guides per deploy** (Cloudflare free plan ≈500 builds/month; budget ≤4 site deploys/day).
- Verify one new page in the browser after deploy.

## 2b. Facebook text posts (Ling, 23 Nov — test)
For EVERY new guide, also write TWO Facebook posts as `site/fbposts/<id>.json` → `{"id":"fb-<keyword-lower>-1","guide":"<slug>","photo":<pexels id that shows that place>,"order":<next number>,"text":"…"}` (second one `-2`). build.py turns them into fb-queue.json; n8n posts the next one 6 times a day (about 08:15, 10:55, 13:25, 16:10, 19:15, 21:45 Malaysia time, each ±5 min at random; Ling 24 Nov: never fixed times) with its designed image. Keep at least 12 unposted posts in the queue (2 days).
- Same topic and facts as the guide, but its own angle; may say we took our time and checked every fact against official listings (true). Example of the approved emotional style: site/fbposts/fb-tenma-1.json. Ling (23 Nov): detailed (250–400 words), English, a small team that knows the place ("we'd", "our take"), warm, specific, never salesy.
- HOOK = the first 1–2 sentences, ONE paragraph, 150–250 characters, no line break inside it. Facebook only shows this before "See more", so it must carry the payoff (a number, a surprising fact, a clear benefit) and end with 👇. Bad: "Second trip to Osaka? Stay where Osaka actually lives." Good: "We priced the same three nights on both sides of Osaka Station. Walking 12 minutes saved ¥9,474. Here's when that walk is worth it, and when it isn't 👇"
- LAYOUT: a BLANK LINE between every paragraph and every point (no stacked bullets). Section headers as one line "🚇 HOW TO GET THERE" (emoji + CAPS), no ━━━ lines. Each point = its own 1–2 sentence paragraph, starting with an emoji or 1️⃣. Link on its own line after "👉 …:". Example: site/fbposts/fb-nakazaki-1.json.
- Post 1 = MINI-GUIDE: situation hook → 2–3 options, each = decision + 1–2 researched whys (numbers from the guide only) → "Our take" → guide link → one easy question.
- Post 2 = one of: INSIDER TIP / MISTAKE TO AVOID (one thing first-timers get wrong + the fix), SAVE-THIS CHECKLIST (3–5 steps), or A-or-B QUESTION. Rotate.
- Insider, lesser-known first: lead with the places and habits regulars know. Dotonbori / Namba / Shibuya crossing / Kabukicho only as a reference point and at most once in any 3 posts; never "the best / must-see" hype.
- CLICKS (Ling, 24 Nov): many people click from Facebook to the site, so give them more chances, with FUN ENGAGEMENT that makes them want to click, not a sales push. Right after the hook, ONE playful click line with the link, e.g. "🤔 Guess first, then check the answer 👉 <url>", "🎯 Bet you can't guess the cheapest option 👉", "👀 One of these surprised even us 👉", "🍱 Hungry yet? The spots, times and prices 👉", "📌 Save this for your trip (the full guide is here) 👉". Use guessing games, A-or-B picks, "which one would you choose?", small challenges, surprise facts; vary them every post. Then the link again at the end with its one-more-thing teaser and a fun question to answer in the comments. "Full guide" is allowed sometimes, but not as the only reason to click. No money talk, no "book now"; we are not monetizing yet: the goal is high-quality content people enjoy and want to open.
- HASHTAGS (Ling, 24 Nov): 10–15 per post on the last line, CamelCase: 2–4 for the exact place (#Tenma #Tenjinbashisuji), 2–3 for the city/region (#Osaka #OsakaTravel #Kansai), 2–3 for the topic (#WhereToStay #JapanFood #JapanTrains), then broad ones (#JapanTravel #TravelJapan #JapanTrip #JapanTravelTips #VisitJapan #JapanGuide). No unrelated tags.
- Every post ends with the guide URL (https://japanbystation.com/<slug>) introduced by its ONE MORE THING, not "full guide" (e.g. "👉 The croquette stop outside the station + the route:") and a question or "save this". No affiliate links, no "cheaper/best price", emojis as bullets only. End with the hashtag line above.
- IMAGE (Ling, 23 Nov): the footer on fbimg.py now reads "Read more on japanbystation.com". Every post gets its OWN designed image, never a plain photo and never the same photo twice. Make it with `python3 fbimg.py <photo.jpg> "<title 2–3 short lines split by |>" "<PLACE, CITY>" site/fbimg/<id>.jpg [focus 0–1]` and add `"image":"fbimg/<id>.jpg"` to the post JSON. The title is the post's promise in 3–7 words ("Walk 12 minutes, save ¥9,474?"). Get the photos like Reel footage: in the built-in browser on a pexels.com tab, fetch the chosen images (images.pexels.com …?w=1600) into ONE bundle file and download it, then split it with device_bash in Downloads/jbs_media/fb and device_stage_files it (method in section 3). Look at the finished image before using it. Mix in neon / night scenes often.
- Photo choice: an eye-catching, clearly Japanese Pexels photo that LOOKS at you (colour, lanterns, food, people, a famous station); it may differ from the exact place, but stay in the same region (Kansai photo for Kansai, Tokyo for Tokyo; never Mount Fuji on an Osaka post). Look at it before using it.
- Emotion: a line or two of feeling (why this moment is worth it), but never claim a stay or visit we didn't make.

## 2c. Page layout and photos (Ling, 24 Nov)
- City hubs are grouped automatically by build.py: "Start here: the big questions" (first-trip where-to-stay, airport, getting around), "Eat and explore like a local", "Day trips and nights away", then "Smart answers for specific situations" as a compact list. A very niche guide must never be the first thing on a city page.
- Walls of text feel like a bombardment: every guide needs a photo at least every 2 sections (3–5 photos per page, each a real photo of that place, `<figure class="photo"><img …><figcaption>…</figcaption></figure>` placed between paragraphs, never two in a row).
- Key points go in dashed boxes (tipbox / bookbox / hotbox / onemore are styled dashed); sections alternate background bands automatically.

## 3. Reels (approved style; do not change without Ling)
### REEL FORMAT v3 (Ling, 23 Nov) — OVERRIDES any older line below that says "three answers" or a comment-only CTA
Reels now carry the same depth as the deep guides. Approved example structure (Tenma, ~35 s):
1. HOOK 0–3 s: the answer + the situation, e.g. "Skip Dotonbori tonight. Osaka eats one stop away, in Tenma."
2. One framing fact 3–6 s (e.g. "A 2.6 km covered street, priced for locals.").
3. TOP 2 PICKS, named and specific: "Number one: Harukoma, the oldest sushi shop on the street. Plates from about ¥100. Go mid-afternoon. Closed Tuesdays." / "Number two: …". Each = name + 2–3 concrete details (price, time, closing day, exit, what to order). Cards "#1 <name> · <key fact>", "#2 …".
4. A LESS-KNOWN DETAIL most people miss ("At Harukoma's tables you write your order on paper, so you don't need Japanese."). It must be on the guide page.
5. ENDING = exciting soft hook with a little emotion, pointing to the guide; vary it. Examples: "That's just the afternoon. The best part happens after dark, and it's all in our guide: link in bio." / "The route that ties it together is in our bio. Or DM us TENMA and we'll send it." / "There's one more stop we'd never skip. It's waiting in our DMs: send TENMA." Main CTAs: link in bio and DM the keyword. "Comment KEYWORD" only now and then (at most 1 Reel in 4). Never "full guide", never pushy.
Caption: hook line + emoji; 🥇 / 🥈 lines with the concrete details; 💡 the less-known detail; the soft-hook CTA (link in bio 👆 / DM KEYWORD); share line; follow line; 5–8 hashtags.
Every fact must be on that guide's page. Shots: max 4 s each, matching the line (rules 5, 5b, 5c).

- Mature male voice with intonation, slow pace (Kokoro blend am_michael 0.65 + am_fenrir 0.35, speed 1.0, built into reelkit).
- Phrase subtitles, outlined text, no background, spoken word bounces in yellow. Small cards in the site palette. Same cover LAYOUT every time (cover.py).
- Real Japan footage WITH PEOPLE, lively, from the right city. No clip used twice in one video (reelkit asserts). Japanese-style music, rotate `m_tokyostroll / m_kyotoriver / m_japansnacks / m_petals`.
- REEL VARIETY (Ling, 23 Nov): in any 3 Reels in a row, "Dotonbori" or "Namba" may appear (voice, cards, cover, caption) in AT MOST ONE. Before writing a spec, read the specs/captions of the last 2 items in reels-queue.json; if either mentions Dotonbori or Namba, this Reel must not. Same for the over-used Tokyo spots (Shibuya crossing, Shinjuku Kabukicho): max once in 3. Lead with places most visitors have not heard of, with a researched why.
- HOOK BY SITUATION, NOT BY PLACE (data, 23 Nov): "Where to stay in Osaka?" / "What's near Namba?" got few views; "Out late in Osaka? Stay here" got 401 viewers + 6 saves + 4 sends. Hooks name the traveller's situation or mistake, then answer at once. Hook styles to rotate: SITUATION ("Landing at 11 pm?", "Out late?", "With a toddler?"), MISTAKE ("Don't book 'near Umeda' before you check the exit"), CONTRAST ("Skip X, do Y instead"), MONEY ("What ¥5,000 really gets you"), TIME ("Only 3 hours in Kyoto?"), LOCAL ("Where Osaka office workers actually eat"). Never two Reels in a row with the same hook style.
- RETENTION RULES (Ling, 23 Nov; every new Reel). Night-owls Reel: 401 viewers, 6 saves + 4 sends (strong topic) but average watch 7 s, because the first answer (Namba) only came at ~12 s after a set-up about last trains. Length 33–40 s is FINE (voiceover 70–95 words); the problem is ORDER. Rules:
  1. ANSWER FIRST, THEN WHY. Open with the recommendation in the first 2 seconds, voice and text together ("Out late in Osaka? Book Namba."), first card already on screen. Never build up to it ("because trains stop at midnight, so book here" is wrong; "Book Namba — you can walk home from Dotonbori in 5 minutes" is right).
  2. SKIP WHAT EVERYONE KNOWS (e.g. "last trains are around midnight"): only say it if it is the reason behind a specific answer, and then after the answer.
  3. THREE ANSWERS, EACH = decision + 1–2 WHYs. Each why is one concrete, researched detail from the guide (minutes on foot, price on a date, last order, which exit). At least one why, at most two, so it is clear we did the research.
  4. Verdict at the end = which one to pick and exactly when the answer changes.
  5. A NEW SHOT AT LEAST EVERY 4 SECONDS (Ling, 23 Nov; reelkit enforces it). Each scene lists its footage in "clips": [["file", start], …], enough for max 4 s per shot (a 9 s scene needs 3). Aim for 2.5–4 s. The Tsuruhashi scene that held one meat shot for ~9 s is the example of what not to do.
  5b. FOOTAGE MUST MATCH WHAT IS SAID (Ling, 23 Nov). A daytime market needs daytime market footage (stalls, produce, shoppers), not night neon; breakfast = morning; nightlife = night. Look at a frame of every clip and check place, time of day and subject against the line it sits under.
  5c. NO VIDEO OF THE PLACE? Use PHOTOS of it with a slow zoom (reelkit does a Ken Burns push-in for .jpg/.png in "clips"). Allowed sources only: Pexels / Pixabay / Unsplash photos (free licence), Wikimedia Commons (CC BY / CC BY-SA / public domain; add "Photo: <author>, CC BY-SA via Wikimedia" to the caption), and official tourism photo libraries whose terms allow use. Never random web / Google Images / Instagram / blog photos: Instagram removes Reels on copyright reports and repeat reports restrict the account (Ling's "don't get banned" rule). Note each photo's source in CLIPS.md.
  6. KEYWORD EARLY: say the keyword once around 8–10 s in passing ("…there's one more stop, comment NIGHT") and again at the end. Cover stays clean (Ling's rule).
  7. Every clip: look at a frame for station names / signs (Tokyo signs never in Kansai Reels).
- Voiceover 70–95 words (about 33–40 s). Start with the most useful finding. Give exactly three answers (the brief's A, B, C), each = the decision first, then 1–2 whys (concrete researched details) and who it suits. Then the verdict: one practical recommendation, and say exactly when it changes (time, price, day of week). Then the CTA scene.
- Spec: `reel/specs/<slug>.json` (copy `reel/specs/osaka-night-owls.json`). Scene 1 = hook, last scene = CTA built from the guide's ONE MORE THING (see ENDINGS below), e.g. "There's a croquette stop right outside the station. Comment NAKA. Follow for more Japan tips." (n8n answers both comments and DMs that contain the keyword.) Every scene uses "clips": [["c_123.mp4", 0.0], ["p_456.jpg"], …] (old single "clip" still works for scenes under 4 s). Middle scenes: the three answers + verdict, each with a card {kicker, title, big number, small}. Cards use only glyphs Poppins has (no №, no arrows; use "No.", "to").
- ENDINGS (Ling, 23 Nov): never "we'll send you the full guide" (anyone can ask AI for a guide) and never anything about clicks or money. The ending teases the guide's ONE MORE THING, answer-first style, and must only promise what that page really contains (read the page first). Vary the wording every Reel; never use the same ending as the last 5 Reels. Patterns: "One more stop worth knowing about — comment X." / "There's a little more that didn't fit in 30 seconds — comment X." / "And there's a breakfast spot right outside the station — comment X." / "Most people walk right past it — comment X." / "Even AI rarely suggests this one — comment X." / "A local bite you only find if you dig — comment X." / "This one took some digging — comment X." (only for a spot that is NOT in the usual English top-10 lists for that area: check a quick web search first) / "Locals have one more stop here — comment X." / "That's the short version — comment X for the rest." If the page has no One more thing yet, use only the "didn't fit in 30 seconds" / "short version" patterns. No dates in endings.
- COVER TEXT (Ling, 23 Nov): titles must be BIG and HIGH so they read on the profile grid (cover.py does this: ONE block centred on the MIDDLE of the photo (grid centre y=960): coral logo-colour "Japan by Station" pill, 108 px white title, place (e.g. "NAMBA, OSAKA") in plain cream text under it; only one pill, NOTHING at the bottom: no "Full guide in DM", no "Comment KEYWORD" on the cover. Ling: covers feel like natural sharing, not a DM ask). Keep cover titles short: 2 lines, about 3 words per line.
- STRANGER TEST (Ling, 23 Nov): assume the viewer is a stranger who has never heard of us. The cover must make it obvious this is about JAPAN: the coral "Japan by Station" pill does that, and the place line always names the place with its city (e.g. "NAMBA, OSAKA", "SHINJUKU, TOKYO", never just "GROUPS"). Where it fits, put the city in the title too ("Out late in Osaka?").
- COVER (first image, Ling's rule): the cover LAYOUT is fixed, but the PHOTO must change every time. Pick a strong, recognisably Japanese frame from that place: street crowds, neon, a temple, a train, food stalls, and seasonal scenes (snow, cherry blossom, autumn leaves) when that place really looks like that. Never reuse a cover clip from the last 12 Reels: check and append to `COVERS.md`. Cover `category` = the PLACE with its city (stranger test); `title` = the brief's question, 2 short lines.
- Caption (`"caption"` in the spec), all relevant to THIS place and question:
  1) hook line + emoji; 2) 3 emoji bullets (the three answers, one concrete detail each); 3) the verdict in one line;
  4) the ENDING line (below) + "Comment KEYWORD 👇" (DMs with the keyword work too); 5) a share line, worded differently every time ("Send this to whoever you're travelling with", "Tag your trip buddy", "Drop this in your group chat");
  6) "Follow @japanbystation for a new Japan tip every day"; 7) 5–8 hashtags last: 2–3 for the exact place (e.g. #kizumarket #namba), 2–3 for the topic (#osakafood #budgethotel), 2 broad (#japantravel #japantrip). No affiliate wording.
- Growth goal from Ling: 400 followers a week. Every Reel must give a real answer, end with the One-more-thing comment CTA, a share CTA and a follow CTA.
- Footage (needs Ling's computer, built-in browser): in a Pexels tab (`https://www.pexels.com/search/videos/<query>/?orientation=portrait`), collect slugs, then in ONE javascript call fetch each video page, take the `1080_1920` (or 720_1280) mp4 URL, fetch the blobs, build one bundle `window._jbs = Blob([10-digit header length, JSON index [[name,size],…], …parts])`, click-download it as `jbs_bundle_<x>.bin`. Ling asked: **bundle downloads into one file**, never one popup per clip.
  In device_bash: the download appears in `$HOME/mnt/Downloads` as a `.tmp` and vanishes fast → poll and `cp` the newest `*.tmp` to /tmp until it reaches the full size, split it with python into `$HOME/mnt/Downloads/jbs_media/`, then `device_stage_files` (Windows paths `C:\Users\User\Downloads\jbs_media\…`) and copy from `/mnt/user-data/uploads/Downloads/jbs_media/` into `reel/air/`.
  Look at one frame of each clip before using it (city, people, really Japan?). Pexels titles lie: an "Asian alley" may be Taiwan. Keep `CLIPS.md` updated (good clips and never-use clips).
- Render: `cd reel && python3 reelkit.py specs/<slug>.json --stills` → Read `work/<slug>/sheet.jpg` and check → `python3 reelkit.py specs/<slug>.json` → check `out/<slug>.jpg` cover.
